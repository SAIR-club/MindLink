## 学习闭环（浏览器自动化，模拟模型）

`tests/workbench-web.test.ts` 中的 *takes a new person from nothing to saved understanding, and back after a restart*，用真实 Edge 跑真实页面：

| 步骤 | 依据 |
|---|---|
| 创建空间 | 页面出现以空间名命名的标题 |
| 导入材料 | 通过材料页的上传控件上传 `编码笔记.md`，计数显示 `材料（1）` |
| 提问，回答带引用 | 出现"查看引用 1：编码笔记.md"；点开后，右侧原文高亮的正是被引用的那句，没有高亮别的段落 |
| 提炼候选 | 点"提炼成待确认的理解"后，计数变为 `待确认（1）`，`我的理解（0）` 不变 |
| 人工审阅并保存 | 点"确认为我的理解"后，计数变为 `我的理解（1）` |
| 重启 | 关闭服务，用同一个图谱文件重新启动 |
| 重启后数据仍在 | 空间、材料、原对话（含引用）、理解都还在 |
| 检索 | 开新对话问相关问题，回答下方出现"你之前确认过（不是材料）" |
| 来自 Core，不是模型生成 | 被列出的那条理解与重启后内核 REST `/api/v1/state` 里的一个节点逐字一致；点开它，页面地址正是 `/understanding/<该节点 id>` |
| 引用关系在重启后依然正确 | 在理解页点"回到当时的对话"，跳回的是最初那段对话（不是新对话），里面的引用 1 还在 |

另外，`tests/workbench-understanding.test.ts` 在接口层确认了几件事：

- 被找回的理解不会算作引用。
- 修订后，只找回最新的说法。
- 有矛盾的理解会带上标记。
- 无关的问题、其他空间里的问题，都不会找回它。

**这一部分覆盖不到的**：回答的措辞来自模拟模型，它只会摘录原句。

## 安装包上的学习闭环（模拟模型）

在开发机上静默安装 `MindLink_0.3.0-rc1_x64-setup.exe`，再用 `tests/rc-smoke.mjs` 在真实 Edge 里驱动已安装程序自己的服务（127.0.0.1:4324）。

注意：这次安装是从 Claude 桌面程序的会话里启动的。这个会话运行在 MSIX 包容器里，Windows 会把 `%LOCALAPPDATA%` 和 `%APPDATA%` 重定向到 `…\Packages\Claude_…\LocalCache` 下面。所以下表里的"程序目录"和"数据文件夹"实际位于这个重定向目录。安装程序和应用本身的行为与普通安装相同。普通用户从资源管理器双击安装时，用的是真正的 `%LOCALAPPDATA%\MindLink` 和 `%APPDATA%\club.sair.mindlink`。验证结束后，这份测试安装已经卸载，测试数据也移出了数据文件夹。

| 步骤 | 结果 |
|---|---|
| 安装（`/S`，当前用户） | 退出码 0；程序装到 `%LOCALAPPDATA%\MindLink`，开始菜单出现 `MindLink.lnk` |
| 第一次启动 | 4 秒后服务开始响应；自动创建 `%APPDATA%\club.sair.mindlink\mindlink.db` 和 `logs\service.log`；用户名含中文的路径正常 |
| 窗口 | 进程 `mindlink-desktop`，窗口标题 `MindLink`，状态为正常响应 |
| 创建空间、导入材料 | Markdown 一份、PDF 一份；PDF 的文字能解析出来，并在原文栏显示 |
| 提问，回答带引用 | 引用 1 高亮的是"自注意力本身不知道词的先后顺序，所以需要位置编码……" |
| 提炼 → 审阅 → 改写后保存 | 候选经"改一改"改成自己的话，再"保存为我的理解"；内核中出现节点 `claim_1`，标签与改写后的文字逐字一致 |
| 强制结束程序进程（模拟崩溃或直接关机） | 服务随程序一起退出，不留后台进程，也不会锁住图谱 |
| 重新打开 | 3 秒就绪；空间、2 份材料、理解都在；内核里仍是 `claim_1` |
| 新对话里检索复用 | 回答下方出现"你之前确认过（不是材料）"，列出的正是 `claim_1` 的文字；点开后地址为 `/understanding/claim_1` |
| 回到当时的对话 | 跳回最初那段对话（不是新对话），引用 1 仍然有效 |
| 升级：在旧版运行时安装新版 | 安装程序关闭旧版后完成安装；数据不变，新版重新跑一遍上面的复用步骤，全部通过 |
| 卸载 | 程序目录删除，数据文件夹保留；重新安装后 `claim_1` 原样还在 |

## 真实模型（Magpie）

**已验证（2026-11-18）。** 用户在已安装程序的"模型"页里自己填写了 Magpie 网关的设置，保存时程序先试连一次，通过后才保存。模型名为 `group/auto-auto`，页面显示为非模拟模型；验证过程没有经手任何凭证。之后在一份全新的数据上，用同一个 `tests/rc-smoke.mjs` 跑完了整个闭环：

| 步骤 | 结果 |
|---|---|
| 提问"为什么需要位置编码？" | 回答来自 `group/auto-auto`（`simulated: false`，`status: answered`），引用 [1] 指向 `课程笔记.md` 中讲位置编码的那一段 |
| 提炼 → 改写 → 保存 | 内核里生成 `claim_1`，内容是用户改写后的那句话 |
| 强制结束进程后重新打开 | 模型设置还在（仍然是 `group/auto-auto`）；空间、2 份材料、理解都在 |
| 新对话问"位置编码有什么作用？" | 真实模型回答"位置编码的作用是把序列的顺序告诉模型，因为自注意力本身不知道词的先后顺序。"，引用 [1] 指向 `课程笔记.md`。回答的 `recalled` 字段里是 `claim_1`，和材料引用分开放，没有被当作引用编号 |
| 点开理解、回到当时的对话 | 地址是 `/understanding/claim_1`；跳回最初那段对话，引用仍然有效 |

这次运行用的是同一种安装方式（从 Claude 会话里安装，安装目录和数据被重定向到包容器下）。测试数据留在那份安装里，没有清理。
